# dsh-plugin-memory-lite

给 DSH 的**本地优先跨会话记忆**：每轮自动沉淀，空闲时自动整理，需要时按需注入。

数据全部存在**本地 SQLite 文件**里 —— 不联网、不上传、不依赖任何外部记忆服务。

---

## 它解决什么

DSH 的会话本身是有记忆边界的：换一个会话、或者一次压缩（compact）之后，
之前聊过的结论就找不回来了。你得反复重新交代"我们用两层架构""那个坑别再踩"。

这个插件在后台做三件事：

| 层 | 做什么 | 什么时候 | 成本 |
|---|---|---|---|
| **日志层** | 每轮结束把对话原样追加到本地 | 自动，每轮 | **零模型调用** |
| **长期条目层** | 把日志里的结论蒸馏成"记忆条目" | **你点「立即整理」时**（也可开启空闲自动） | 每次一次模型调用 |
| **注入层** | 把你这句话相关的记忆作为**独立消息**追加到对话尾部 | 自动，每轮 | 零成本 |

**日志层永远不进提示词** —— 只有蒸馏后的条目才会被注入。
否则上下文预算和前缀缓存都会被日志淹没。

## 安装

```
dsh plugin --profile <你的profile名> add github:eighteentang/dsh-plugin-memory-lite#v1.1.0
```

装完后**重启客户端**，设置页会出现 **「记忆控制」**。

> **`#v1.1.0` 是版本钉子** —— 钉住版本避免"装到一半上游改了"。
> 去掉 `#…` 就是跟随主分支（自动拿到新改动，也自动拿到新 bug）。
> 全部版本见 [CHANGELOG.md](CHANGELOG.md)；升级就是把版本号换掉重新执行一次。

> 开发期用 `link:` 装（`link:D:/path/to/memory-lite`）也是支持的，
> 但**必须保留 `peerDependencies`**，否则插件的包解析会失败。

## 怎么用

### 平时不用管

- 每轮对话结束，它自动把这一轮记下来（不花模型额度）
- 每句用户消息到达时，它按关键词找相关记忆，注入到对话尾部
- **整理成条目默认要你手动点**（避免"没打招呼就花额度"）。
  想让它自己长出来，把 `autoDistill` 设成 `true` —— 那样空闲 30 分钟后会自动整理
  （每天最多 4 次，见下面配置）。

### 想手动做点什么

- **设置页 →「记忆控制」**：看全部记忆、按层级/状态筛选、搜索、改状态、点「立即整理」
- **对 DSH 说**（这些是模型可见的工具）：
  - 「记住：这个项目用两层记忆架构」→ `memory_note`
  - 「搜一下我之前说过关于注入的东西」→ `memory_search`
  - 「把那条标记成已完成」→ `memory_update`
  - 「忘了那条吧」→ `memory_forget`（**删除需要你点头**，走审批）

### 三种状态

| 状态 | 含义 | 之后会怎样 |
|---|---|---|
| **在用** | 内容有效，可能被召回 | 正常参与注入与检索 |
| **已完成** | 这件事做完了（todo 完成、话题达成目标） | **内容仍然有效**，仍可被搜到与召回 |
| **已停用** | 这条不再正确或不再需要（过时、被取代、写错了） | 不再被注入，但仍可搜到、**可随时恢复** |

## 数据在哪

```
<工作区>/.dsh-memory/memory.db        ← 记忆库（每个工作区一个）
<工作区>/.dsh-memory/archive/         ← 日志溢出后的归档（jsonl）
$DSH_HOME/memory-lite/workspaces.json ← 库 → 工作区 的注册表
```

**删除记忆**：三种方式，按彻底程度

1. 设置页把条目改成「已停用」—— 不注入了，但还在库里（**推荐**，可恢复）
2. 用 `memory_forget` 工具删单条 —— 需要审批
3. 直接删 `.dsh-memory/` 目录 —— **全部记忆消失**，不可恢复

## 配置

在 profile 的 `cordis.patch.yml` 里给插件加 `config`：

```yaml
- id: memory-lite
  name: dsh-plugin-memory-lite
  config:
    autoCapture: true             # 每轮自动落日志（不花额度）
    autoRecall: true              # 每轮按关键词注入（不花额度）
    autoDistill: false            # 空闲自动整理 —— 默认关（会花模型额度）
    distillIdleMinutes: 30        # 开启 autoDistill 时：多久没说话才算"空闲"
    distillMinIntervalMinutes: 30 # 开启 autoDistill 时：两次整理之间的最小间隔
    distillMaxPerDay: 4           # 开启 autoDistill 时：每天最多整理几次（成本硬上限）
    injectMaxItems: 3             # 单次最多注入几条
    injectMaxChars: 2000          # 单次注入的字符上限
    crossWorkspaceSearch: true    # 允许跨工作区检索
    distillProvider: ''           # 留空 = 用会话默认模型
    distillModel: ''
```

**关于花额度**：默认 `autoDistill: false` —— 日志照记，但**只有你点「立即整理」时**才会调用模型。
想让它自己长出来就把 `autoDistill` 设成 `true`，那时上面三个 `distill*` 参数才生效
（空闲多久算闲 / 冷却 / 每天上限）。

## 设计上的几个刻意选择

这些都是**踩过坑之后**定下来的，改动前请先读 `AGENTS.md`：

- **注入只走长期层**。日志层永不进提示词，否则前缀缓存失效、上下文预算被淹。
- **注入是"只追加"**：作为独立消息追加在本轮已领取消息之后，不改写已有历史。
- **不重复注入**：同一会话里已注入过的条目不再注入；压缩后重置这个记录并**补回常驻记忆**。
- **敏感内容 fail-closed**：`sensitive` 在**写入时**算一次并落列，注入时只读列。
  注入路径上再判断，等于把 fail-closed 变成 fail-open（判断代码出错就注入了）。
- **删除走审批**：`memory_forget` 声明为破坏性工具，转人工确认。
- **超预算的日志留到下次**：不"发都没发出去却记成处理过了"——那会永久丢内容。

## 已知限制

- **检索是关键词级的**，不是语义向量检索。中文查询按连续串与子串匹配，
  所以**换个说法可能搜不到**（用 `memory_search` 时尽量带上你当时用的词）。
- **每个工作区一个库**，默认只搜当前工作区；跨工作区要显式 `scope="all"`。
- 日志层有容量上限（每会话约 200 条），超出会**先写归档文件再删库内行**（不静默丢）。
- 空闲自动整理依赖宿主进程活着 —— 客户端关着的时候不会整理。
